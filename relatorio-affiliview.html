1. Prova de Integridade — Por que os dados estão corretos

O AffiliView puxa dados diretamente da API Digistore24, sem intermediários, sem cache, sem transformações arbitrárias. A prova de que os dados estão corretos é simples: a API retorna um campo summary calculado pelo servidor da Digistore — e nossos cálculos batem exatamente:

2. De onde vem cada dado

O pipeline é direto: API Digistore24 → Proxy (injeta API key no servidor, nunca exposta) → Normalização (campo→campo) → Cálculo → Dashboard.

Upsells não são um "tipo" separado na API — vêm como transaction_type: "payment" com upsell_no ≥ 1. Por isso não filtramos por tipo de upsell — já vem tudo junto.

3. O campo certo para cada métrica

A API Digistore retorna vários campos de valor por transação. A escolha do campo correto é crítica:

CampoPara PaymentsPara RefundsReembolso Parcial (30%)
amountValor pago pelo compradorValor original do pedidoMostra €294 (pedido inteiro)
transaction_amountValor pago (mesmo que amount)Valor efetivamente devolvidoMostra −€88,20 (correto)
earned_amountGanhos do produtorEstorno dos ganhosMostra −€74,31 (correto)
Por que isso importa: Dos 109 refunds no período, 25 são parciais (23%). Se um sistema usa amount em vez de transaction_amount, infla os refunds em €3.982 — uma superestimação de ~1,9 pontos percentuais na taxa de reembolso. O AffiliView usa o campo correto.

Por que inclui upsells: A documentação oficial da Digistore define "Gross Amount" como "initial sales, upsells, subscription and installment payments". Excluir upsells causava divergência de -13,4% (corrigido na Phase 8).

Por que não deduz refunds: Refunds são transações separadas — afetam Earnings (via earned_amount negativo), não Gross.

O que é earned_amount: É o valor final que a Digistore deposita na sua conta, após deduzir IVA, margem Digistore (7,9% + $1), comissão do afiliado e reserves. A API já entrega o campo assinado — somamos direto, sem transformação.

Por que inclui upsells: A documentação oficial define "Your Earnings" como "all commissions from vendor business including initial sales, upsells, subscription and installment payments". Excluir upsells causava divergência de -48,3% (corrigido na Phase 8).

4.3 Valor Líquido

= EarningsFront − COGS = (Earnings só de front + refunds front) − (Custo produto + Frete)

Por que só front: COGS aplica-se a produtos físicos (Slimjara, Erectus X, Memoguard) que precisam de envio. Upsells são digitais — sem custo de fulfillment. Misturar earnings de upsells com COGS de fronts distorceria a margem.

Não tem equivalente no painel Digistore — é métrica proprietária do AffiliView.

4.4 AOV (Ticket Médio) — €265,11

= SUM(amount − vat_amount WHERE payment) / COUNT(payment WHERE upsell_no = 0)

Por que exclui VAT: O amount inclui IVA. Subtrair vat_amount dá o valor real do negócio.

Por que divide por front sales: Cada upsell é uma adição ao mesmo pedido — dividir por (front + upsells) subestimaria o valor real por pedido.

6. Por que o relatório interno Digistore pode divergir

#CausaEfeito
1Timezone: Dashboard Digistore usa CET (UTC+1/+2); API retorna UTC. Transações perto da meia-noite caem em dias diferentes.±1 dia nas bordas do período
2Role combinado: Se você gera earnings como vendor E como afiliado, o dashboard Digistore soma ambos. A API com role=vendor separa.Dashboard Digistore pode ser maior
3"Gross" diferente: O campo total_amount da API = pagamentos − refunds − CB (líquido). Não é "Gross Revenue" (só pagamentos).Comparação incorreta se cruzar os campos
4Reembolsos parciais: Se usa amount (original) em vez de transaction_amount (efetivo), as taxas ficam infladas.~1,9pp de superestimação
5Estimativas: A documentação oficial afirma que valores do dashboard são estimativas — chargebacks e fees podem alterar valores finais.Variação natural

Conclusão: O AffiliView extrai dados diretamente da API Digistore24. O Earnings bate 100% ao centavo com o summary do servidor. Cada métrica usa o campo API correto, documentado e justificado. A taxa de reembolso usa |transaction_amount| para tratar parciais corretamente. Todas as 10 KPIs do dashboard, 6 métricas por afiliado, e as tabelas de produto foram auditadas e estão condizentes com os dados extraídos. Divergências com o painel interno Digistore são explicadas por diferenças de timezone, escopo de role e campos de referência — não por erro no AffiliView.
